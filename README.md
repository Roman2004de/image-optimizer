# Image Optimizer (Bash)

Bash-скрипт для рекурсивной оптимизации изображений **JPG, JPEG и PNG** в каталоге Linux-сервера. Предназначен, в частности, для уменьшения объёма медиафайлов на веб-сайтах без изменения путей к изображениям.

По умолчанию работает в режиме предварительного просмотра (**preview**) и **не изменяет файлы**. Для оптимизации необходимо явно указать `--apply` и отдельный каталог резервных копий.

## Возможности

- Рекурсивный обход каталогов любой глубины с помощью `find`.
- Поиск файлов `.jpg`, `.jpeg`, `.png` без учёта регистра расширения.
- Фильтрация по размеру; по умолчанию **строго больше 1024 КиБ (1 МиБ)**.
- Оптимизация JPEG через `jpegoptim` с ограничением качества (по умолчанию `85`). **С потерями качества**, если это требуется для сжатия.
- Оптимизация PNG через `optipng -o2` **без потери качества**.
- Замена исходного файла только в том случае, если оптимизированная версия меньше.
- Создание резервной копии исходного файла перед заменой, с сохранением относительного пути.
- Отчёт по количеству найденных, оптимизированных и пропущенных файлов, ошибкам и экономии объёма.
- Корректная обработка пробелов и специальных символов в путях, в том числе символов перевода строки.

Скрипт **не изменяет ширину и высоту** изображений, не конвертирует их в WebP/AVIF и не обрабатывает форматы за пределами JPG/JPEG/PNG.

## Требования

- Linux с Bash, GNU `find`, GNU `stat`, GNU `cp`, GNU `mktemp` и стандартными утилитами GNU coreutils.
- `jpegoptim` и `optipng` — необходимы при запуске с `--apply`.
- Права чтения исходных файлов, записи в исходные каталоги и каталог резервных копий.
- Достаточно свободного дискового пространства для временных файлов и резервных копий.

### Установка зависимостей

**Debian / Ubuntu:**

```bash
sudo apt update
sudo apt install jpegoptim optipng
```

**AlmaLinux / Rocky Linux** (доступность пакетов зависит от версии и подключённых репозиториев):

```bash
sudo dnf install epel-release
sudo dnf install jpegoptim optipng
```

Проверка:

```bash
jpegoptim --version
optipng -v
```

## Быстрый старт

```bash
chmod +x optimize_images.sh

# Сначала вывести список подходящих файлов — никаких изменений
./optimize_images.sh /var/www/yalta/data/www/yalta-official.ru/upload

# Затем выполнить оптимизацию с резервным копированием
./optimize_images.sh \
  /var/www/yalta/data/www/yalta-official.ru/upload \
  --apply \
  --backup-dir /var/backups/yalta-images \
  --quality 85
```

> **Важно:** каталог резервных копий должен находиться **за пределами** обрабатываемого каталога. Не запускайте массовую оптимизацию на работающем сайте без предварительного полноценного бэкапа и проверки нескольких файлов.

## Параметры

| Параметр | Описание | По умолчанию |
|---|---|---|
| `DIRECTORY` | Обязательный первый аргумент: каталог изображений | — |
| `--apply` | Включить изменение файлов | Выключен (preview) |
| `--backup-dir PATH` | Куда сохранять оригиналы; обязателен с `--apply` | — |
| `--min-kb N` | Минимальный размер файла в КиБ (1024 байта); выбираются файлы **строго больше** указанного размера | `1024` |
| `--quality N` | Максимальное качество JPEG, число от 1 до 100; не влияет на PNG | `85` |
| `-h`, `--help` | Показать справку (при переданном аргументе каталога) | — |

`--min-kb` принимает положительное целое число. Например, `--min-kb 500` соответствует порогу **512 000 байт**.

### Предварительный просмотр с порогом 500 КиБ

```bash
./optimize_images.sh \
  /var/www/yalta/data/www/yalta-official.ru/upload \
  --min-kb 500
```

### Оптимизация JPEG с другим уровнем качества

```bash
./optimize_images.sh \
  /var/www/yalta/data/www/yalta-official.ru/upload \
  --min-kb 500 \
  --quality 90 \
  --apply \
  --backup-dir /var/backups/yalta-images
```

Чем ниже значение `--quality`, тем потенциально меньше JPEG-файл, но тем заметнее могут быть визуальные артефакты. Рекомендуется начинать с `85–90` и проверять результат визуально.

## Алгоритм работы

1. Проверяет каталог и значения параметров.
2. В режиме `--apply` проверяет наличие `jpegoptim` и `optipng`, а также расположение каталога резервных копий.
3. Через `find` находит подходящие файлы и последовательно обрабатывает их.
4. Создаёт временную копию в том же каталоге, что и оригинал.
5. Оптимизирует временный файл соответствующей утилитой.
6. Если размер не уменьшился, удаляет временный файл и оставляет оригинал без изменений.
7. Если размер уменьшился, сохраняет оригинал в `--backup-dir` и заменяет его оптимизированным файлом.
8. Выводит статистику выполнения.

При замене скрипт переносит на оптимизированный файл права доступа и время изменения; при запуске от `root` также восстанавливает владельца и группу. Для JPEG применяется `jpegoptim --strip-none`, чтобы не удалять метаданные намеренно.

Если по соответствующему пути резервная копия **уже существует**, файл пропускается. Это предотвращает перезапись прежнего оригинала, но означает, что повторная оптимизация того же файла с существующей резервной копией не выполняется.

## Пример вывода

```text
[OK] saved 842152 bytes: /var/www/example/upload/photo1.jpg
[OK] saved 375210 bytes: /var/www/example/upload/photo2.jpeg
[UNCHANGED] /var/www/example/upload/banner.png

Scanned: 3 | Optimized: 2 | Skipped: 1 | Errors: 0 | Saved: 1.16 MiB
```

Пример иллюстративный; фактическая экономия зависит от исходных изображений.

## Восстановление оригиналов

Резервные копии сохраняют относительную структуру каталогов. Например:

```text
Источник:
/var/www/yalta/data/www/yalta-official.ru/upload/news/photo.jpg

Резервная копия:
/var/backups/yalta-images/news/photo.jpg
```

Чтобы восстановить **один** файл:

```bash
cp -p \
  /var/backups/yalta-images/news/photo.jpg \
  /var/www/yalta/data/www/yalta-official.ru/upload/news/photo.jpg
```

Перед массовым восстановлением проверьте пути и наличие более новых изменений на сайте: копирование поверх текущих файлов может уничтожить эти изменения.

## Статусы и завершение

- `[PREVIEW]` — найден файл в режиме просмотра.
- `[OK]` — исходный файл заменён уменьшенной версией.
- `[UNCHANGED]` — оптимизированный файл не стал меньше.
- `[SKIP backup exists]` — резервная копия по указанному пути уже существует.
- `[ERROR optimizer]` / `[ERROR backup]` — ошибка обработки или копирования.

Код выхода `0` означает, что скрипт не зафиксировал ошибок обработки; ненулевой код указывает на ошибку параметров, проверки или обработки. **Ограничение:** ошибки самого `find` в текущей реализации не учитываются надёжно в итоговом коде выхода, поэтому следите также за сообщениями на `stderr`.

## Ограничения и меры предосторожности

- **Не запускайте одновременно несколько экземпляров** на одном каталоге: скрипт не использует блокировку и не защищён от параллельной модификации файлов сайтом.
- На время обработки желательно исключить загрузку и изменение этих изображений другими процессами.
- Временные файлы создаются рядом с оригиналами, а при замене используется `mv`. При аварийном завершении временные файлы могут остаться.
- Символические ссылки не обходятся (`find -type f` без следования ссылкам).
- Жёсткие ссылки требуют отдельной проверки: замена файла через `mv` не обновляет другие ссылки на прежний inode.
- Не гарантируется сохранение ACL, расширенных атрибутов и SELinux-контекстов. При необходимости проверьте их отдельно.
- Каталог резервных копий занимает место: пока оригиналы остаются там **на том же файловом разделе**, снижение общего использования диска может не произойти.
- Для JPEG возможны потери качества. PNG оптимизируется без потери качества, но значительная экономия не гарантируется.
- Скрипт не проверяет визуальную корректность результата и не сравнивает изображения попиксельно.
- Скрипт проверяет расширения, а не фактический MIME-тип файлов.
- На рабочих сайтах после замены файлов может потребоваться очистка кеша изображений и CDN.
